# ADR 001: Rule 패턴 분리 (ThresholdRule vs RapidRiseRule)

## 상태

승인됨

## 컨텍스트

공기질 데이터의 이상 패턴을 감지하기 위해 두 가지 주요 패턴이 있습니다:
1. **임계치 초과**: 특정 값이 기준치를 넘는 경우
2. **급상승**: 단시간 내에 값이 급격히 상승하는 경우

이 두 패턴은 서로 다른 비즈니스 로직을 가지고 있으며, 각각 다른 방식으로 평가됩니다.

## 결정

두 가지 룰을 별도의 클래스로 분리했습니다:
- `ThresholdRule`: 임계치 초과 감지
- `RapidRiseRule`: 급상승 감지

두 클래스 모두 `AnomalyRule` 인터페이스를 구현하여 공통 인터페이스를 제공합니다.

## 고려한 대안

### 대안 1: 단일 Rule 클래스에 모든 로직 포함

```kotlin
class AnomalyRule(
    val type: AnomalyType,
    val threshold: Double?,
    val rapidRiseDelta: Double?
) {
    fun evaluate(...) {
        // 복잡한 조건문으로 모든 케이스 처리
    }
}
```

**장점**:
- 클래스 수가 적음
- 모든 로직이 한 곳에 있음

**단점**:
- 단일 책임 원칙 위반
- 조건문이 복잡해짐
- 확장성이 떨어짐
- 테스트가 어려움

### 대안 2: 현재 선택 (분리된 Rule 클래스)

**장점**:
- 단일 책임 원칙 준수
- 각 룰이 독립적으로 테스트 가능
- 새로운 룰 타입 추가가 용이
- 코드 가독성 향상

**단점**:
- 클래스 수가 증가
- 공통 로직 중복 가능성 (하지만 현재는 없음)

## 결과

- 각 룰이 명확한 책임을 가짐
- 새로운 룰 타입 추가가 쉬움 (예: `SuddenDropRule`, `PatternRule`)
- 테스트 작성이 용이함
- 코드 유지보수가 쉬움

## 참고

- Strategy 패턴 적용
- Open/Closed 원칙 준수
